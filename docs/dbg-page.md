# 调试器页（`#dbg`）—— 零安装的极简调试前端

> 目标：**不装任何软件**，在浏览器里对目标做平时最常用的那几件事 ——
> 暂停 / 继续 / 单步 / 复位、看改寄存器、看改内存、下硬件断点、按符号名看变量、
> 浏览**符号列表**、把变量丢进**监视窗口**、停下来显示**当前源码行**，顺手在旁边看 RTT 的 printf。
> 明确**不做**：反汇编、局部变量（DWARF 表达式求值）、RTOS 感知、多核、软件断点。
>
> 入口：`index.html#dbg`（或双击 `start-web.bat` 后点「调试器」）。

## 1. 分层（改代码前先认门）

| 文件 | 职责 | 能不能在 Node 里自测 |

| `app/dbg/regs.js` | 内核寄存器表、xPSR 拆位、**CFBP 的字节打包** | ✅ 纯函数 |

| `app/dbg/view.js` | 只管 DOM（表格、dump、按钮、日志、观察循环、源码视图、终端手感） | ❌ 用 CDP 测 |

自测：`make test-dbg`（纯 Node，157 项）、`make test-dbg-page`（CDP 真页面，98 项）、
`make test-dbg-hw`（真探针 + 真目标板的冒烟：连接 → 读 IDCODE/寄存器/内存 → 暂停/单步/继续 →
试一个断点再删掉 → 符号列表/监视/源码行；**只读为主**，跑完把目标放回运行状态）。
> ⚠️ 真机那条的前提是**探针没被别的程序占着**：同一个浏览器的别的页签、或另开的浏览器
> （Chrome/Edge）里还连着探针时，`claimInterface` 会报 `Unable to claim interface` ——
> 脚本会明确提示并跳过，不会假装成功。
>
> ⚠️ 真机冒烟会**先「暂停」再读寄存器**（脚本自己保证幂等）：目标可能是上一次冒烟放跑的运行状态，
> 不停下来就读不到寄存器。单步那一条若目标正卡在 `b .`（HardFault 死循环，PC 处机器码 `fe e7`），
> 脚本打印诊断并**跳过**而不是判失败 —— 那是目标的状态，不是调试链的锅。

## 2. 底座是复用的，没有另起一套

`app/rtt/dap-webusb.js` 的 `WebUsbDapProbe` 早就把最难的部分写完了：
`halt/run/isHalted/_dhcsr`、`regRead/regWrite`（DCRSR/DCRDR）、`readMem/writeMem`、
`_targetInit`（SWJ 激活 + DP 上电 + CSW 试配）。调试页只是在它上面加了三件事：
**硬件断点（FPB）**、**单步**、**抢占纪律**。

## 3. 三条硬约束（踩过的，别改回去）

### 3.1 PPB 访问必须 ≤1 MHz
`DHCSR/DCRSR/DCRDR`、`FPB`、`AIRCR` 都在 `0xE0000000` 这一片（PPB）。这颗探针固件在时钟偏高时
**读回 0**（烧录/读 IDCODE 那边早就强制 1 MHz）。所以页面上那格默认 **1000 kHz**，别"顺手调高"。
（RAM 读写在 8~12 MHz 下没问题，但为了一次会话只协商一次时钟，这里统一按 1 MHz。）

### 3.2 命中断点后"继续"必须先跨过它
FPB 是"取指地址命中就停"，命中后 PC **停在断点那条指令的地址上** ——
直接 `C_HALT=0` 让它跑，它会立刻再命中一次，用户看到的是"点了继续没反应"。
`session.cont()` 的做法与 gdb/pyOCD 一致：**临时摘掉那个比较器 → 单步一条 → 装回比较器 → 继续**。
`step()` 里同样要摘（否则"在断点上单步"原地不动）。

### 3.3 CFBP 的字节顺序（查过权威实现，不是猜的）
`DCRSR.REGSEL = 0x14` 返回一个打包值：

| 字节 | 寄存器 |
|---|---|
| `[7:0]` | PRIMASK |
| `[15:8]` | BASEPRI |
| `[23:16]` | FAULTMASK |
| `[31:24]` | CONTROL |

依据 OpenOCD `src/target/armv7m.c`（`*offset = arm_reg_id - ARMV7M_PRIMASK`，按 `offset*8` 取字节）
与 pyOCD（`(val >> ((reg & 3) * 8)) & 0xff`）。写单个特殊寄存器走**读-改-写**，别把兄弟字节冲掉。

## 4. FPB（硬件断点）要点

* 寄存器：`FP_CTRL=0xE0002000`（bit0 ENABLE、bit1 KEY **必须同时置 1**）、`FP_COMPn=0xE0002008+4n`。
* 比较器个数：`((ctrl >>> 8) & 0x70) | ((ctrl >>> 4) & 0x0f)`；版本 `1 + (ctrl >>> 28)`（0→rev1、1→rev2）。
  真机 Cortex-M7 读到 `0x82` → **8 个**。
* 编码（照抄 pyOCD `fpb.py`，真机久经考验）：
  * rev1：`comp = (addr & ~3) | BP_MATCH | 1`，`BP_MATCH` = 上半字 `2<<30` / 下半字 `1<<30`；
    **只能匹配 `0x20000000` 以下**（所以 H7 的 QSPI 代码 `0x9…` 打不了）；解码时 bit1 要从 `BP_MATCH` 还回来。
  * rev2：`comp = (addr & ~1) | 1`，地址不限。
* 删断点 = 往比较器写 0；最后一个断点删掉后 `FP_CTRL = KEY|0`（关掉整个 FPB）。
* 写完全部比较器**必须回读对账**：这颗探针的 PPB 写偶发不落地，断点静默失效最难查。
* 接手时**清掉上一次会话残留的比较器**（标准调试器行为），否则目标会"莫名其妙停住"。

## 5. 会话与运行流程

```
连接   → 请别的页签让出探针（probe-bus）→ 停掉「RTT 转发」的探针桥（HID 0x31 action 0）
       → 关掉本页签残留的探针句柄 → WebUsbDapProbe.open(clockKhz=1000)
       → 读 DHCSR 判断"在跑/停住" → 读 FP_CTRL 得到断点容量
继续   → 先清 DFSR → （PC 在断点上就先单步跨过）→ 写 DHCSR = 0xA05F0001
暂停   → 写 DHCSR = 0xA05F0003
单步   → 写 DHCSR = 0xA05F000F（DEBUGEN|HALT|STEP|MASKINTS）
         然后**先看到 S_HALT 变 0、再看到它变 1**；只等"=1"会立刻返回（等于没等）
复位   → 写 AIRCR.SYSRESETREQ（0x05FA0004），**不用探针的 nRESET 引脚**
         （本机好几块板没把 NRST 接给探针，"拉复位"看着成功其实没动）
```

界面侧还有一个**观察循环**（`view._watchLoop`）：点「继续」之后每 150 ms 读一次 DHCSR，
停住时刷新寄存器、报"命中断点/已停止"，并在开着 RTT 时顺手泵一次 RTT 上行。
短等待一律用 `core/pace.js` 的 `waitMs`（`setTimeout` 在页面不可见时会被钳到 ≥1 s）。

## 6. 假目标（`app/dbg/mock.js`）—— 自测的"标准答案"

没有硬件也能把整条链跑通，靠的是这个假目标。它刻意**照真硬件的行为**建模，
下面两条一旦偷懒，测试就会"全绿但线上全错"：

1. **读 DHCSR 不能回显 DBGKEY(0xA05F)**：钥匙只在**写**的时候给。把 `0xA05F` 或进读数会让
   bit17（S_HALT）恒为 1 → "目标明明在跑、读回来永远是已停止"。（本仓真踩过。）
2. **单步要能看到 S_HALT 的 0→1**：上层就是靠这个过程判断"这一步真的执行了"。

另外：一次字读的 4 个字节必须返回同一个值（上层是逐字节读的，每次重新采样会拼出假状态）；
FPB 比较器用**真的** `bp.js` 编解码（编码写错 → "断点永远不命中" → 测试变红）；
RAM 里放了一个结构合法的 **RTT 控制块**（`0x20000100`），跑起来会往环里写
`[dbg] tick N @0x…`，页面上的「RTT 输出」因此也能被自测覆盖。

## 7. 界面约定

> 版式（2026-10-02 照 Ozone 的意思重排，用户点名要求）：
> **左边一列** = 源码（上，默认占大头）+ 命令行（下，默认 `38%`），中间一条**可拖的横分隔条**；
> **右边一条「局部 tab」面板**顶到满高，四个 tab = **寄存器 / 内存 / 变量 / RTT** 一次只显示一个 ——
> 不再把四块平铺成小格子（那样每块都太小）。左边与右边之间还有一条**可拖的竖分隔条**。
> 两处尺寸都记在 localStorage（`dbg.dockW` / `dbg.termH`），tab 选择记在 `dbg.dock`。
> 窗口窄于 1240px 时右侧面板自动折到下面（仍是一整条 tab 面板）。

* 寄存器表（**寄存器 tab**）：每行一个输入框，**回车即写**（读回不一致会黄字提醒；有些位是只读的）。
  与上次相比**变了的值**整行标黄。PC/LR 那一行还带 `函数+偏移` 与 `文件:行`。
* 内存（**内存 tab**）：地址 + 长度（1~1024）→ hexdump；勾「可写」后**点某个字节**会把地址/原值填进「改」那一行，
  回车或点「写入」下发，写完自动回读对账。
  「内存跟随 PC」勾上时，停下就自动跳到 `PC & ~0xF`。
  hexdump 一行几个字节**按面板宽度自适应**（<560px 时一行 8 个，否则 16 个），窄面板里不会横向溢出。
* **符号列表**（**变量 tab** 上半）：载入 ELF 后列符号 —— **带类型的全局/静态变量排在最前**，
  然后函数，最后是没有类型的数据对象；上面那个输入框按子串过滤（最多渲染 300 行，超了会提示缩小范围）。
  **点名字** = 把 `p <名字>` 填进命令行；**点 ＋** = 加进监视窗口。
* **监视窗口**（**变量 tab** 下半）：`w <变量>` / 符号列表的 ＋ / 那个输入框都能加；`wl` 列出、`wd <编号|名字|all>` 删。
  取值时机 = **目标停下来时自动读一遍**（暂停 / 命中 / 单步后都会刷），
  勾上「运行中也刷新」则运行中约 4 次/秒从 RAM 直读（值可能读到写一半的，且占用 SWD）。
  表达式支持 `变量名` / `符号+偏移`（按 u32 读）/ `0x20000000`；**不支持** `a[3]`、`s.member`（见 §8）。
* **源码视图**（左上那块）：停下来（暂停/命中/单步）时按 PC 查行号表，显示 `文件:行` 与上下文，
  当前行高亮、已下断点的行号标红；**点行号 = 在这行下/删硬件断点**（行号表里没有地址的行会明说。
  例如空行、声明、被优化掉的行）。
  看得到**代码文本**需要先点「选择源码目录…」授权一次工程目录（见 §7.1）。
* 命令行（左下那块，xshell 手感）：`h` 看全部命令；**Tab 补全**（命令名 / 符号 / 寄存器 / 断点号 / 源文件名，
  多个候选时先补公共前缀、再按一次 Tab 列出候选）；`↑↓` 翻历史；`Ctrl+C` 中断当前命令、
  `Ctrl+L` 清屏、`Ctrl+A/E/U/K/W` 行编辑；**粘贴多行会排队逐条执行**；
  点输出区（没在选文字时）把焦点还给输入行。常用命令：
  `r` / `r r0 0x1234` / `md 0x20000000 64` / `mw 0x20000000 01 02` / `p g_var` / `w g_var` /
  `b main` / `bl` / `bd 1` / `c` / `s` / `reset run` / `sl` / `src main.c:120` / `info` / `sym RTT`。
  认不出的命令**报错**（不静默），解析失败绝不猜（比如 `md 0x2000 abc`）。
  > `Ctrl+C` 只能"跑到下一步就停"：浏览器没法取消**正在飞的 USB 传输**，
  > 所以按下去之后当前那一笔写完才生效（cmd.js 里每个操作前后都有 `checkCancel`）。
* 侧栏「断点」列表点 `×` 直接删；「RTT」（**RTT tab**）那一栏会**显示 ELF 里 `_SEGGER_RTT` 的地址**
  （地址格留空就用它；手填了就以手填为准），另外也会尝试 `SEGGER_RTT` / `g_rtt` 等别名。

### 7.1 「停下来显示当前源码行」是怎么工作的

1. **行号表**：`app/elf/lines.js` 解析 `.debug_line`（DWARF 2~5 都认，v5 的目录/文件表是
   "格式描述 + 值"两段式），把每个 CU 的行号程序跑成**地址区间**，于是 `at(pc)` 能给出 `文件:行`。
   载入 ELF 时会顺带解析（`SymTab.lines`），失败**不算致命**：符号/变量/断点照常用，只是没有源码行。
2. **源码文本**：浏览器读不到你磁盘上的 `.c`，必须由用户授权一次：
   * Chromium 系点「选择源码目录…」→ `showDirectoryPicker()`（`http://127.0.0.1` 与 https 下可用），
     句柄留着，之后按需读文件；
   * 老浏览器/不想授权就用旁边隐藏的 `<input webkitdirectory>` 那条路（选文件夹 → File 快照）。
   ELF 里记的是**编译机上的绝对路径**（可能是同事机器的 `E:/proj/...`），所以 `source.js` 的
   `resolve()` 从**最长后缀**开始逐级匹配，再退到"同名文件唯一就认它"；匹配不上就老实说"没找到"。
3. **伪源码**（`mock.js` 里）：假目标有寄存器/内存，若喂同一个真 ELF 也能按 PC 显示行号 —— CDP 自测
   就是这么覆盖这条链的（塞一个假的"文件仓"给视图，验证取到文本之后的渲染/高亮/断点标记）。

## 8. 已知边界

| 不做 | 原因 |
|---|---|
| 反汇编 | Thumb-2 解码表几千行 / RISC-V 另一套，与"零依赖"冲突；用 `sym` + 符号落点代替 |
| 局部变量 / 表达式 | 要 DWARF 表达式求值（寄存器里、栈上偏移），无底洞；只支持全局/静态变量 |
| 软件断点 | flash 上要擦一页再写回；RAM 上会破坏"同一份固件两种跑法" |
| `0x20000000` 以上的断点（rev1 FPB） | 硬件比较器只有 27 位地址，`0x9…` 的 QSPI 代码打不了 |
| 监视里的 `a[3]` / `s.member` | 要完整的 DWARF 类型图（元素类型/成员偏移），J-Scope 那套的活；这里是"停下来瞅一眼"的最小集 |
| 行号表里的**内联函数** | `at()` 只做"地址 → 行"，不做 `DW_TAG_inlined_subroutine` 展开（不求 gdb 级调用栈还原） |
| RISC-V/JTAG 的运行控制 | 那条路的 halt/step 走 DM 的 `dmcontrol`（`app/flash/hpm/riscv-dm.js` 已有），
但寄存器组要经 progbuf 搬，v1 没做；本页只做了 SWD/ARM |
| 桥 + OpenOCD/J-Link 的 GDB RSP 兜底 | 计划中（覆盖 OpenOCD 支持的全部芯片，断点免费） |
