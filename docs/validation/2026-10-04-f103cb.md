# 2026-10-04 补丁逐项验收：akaLinkPro + STM32F103CB

两仓库的补丁逐项验证后逐项提交到本地 main：探针 10 项，网页 90 项（原 72 项加新增 18 项）。未推送远端。完整补丁哈希已与 SHA256SUMS 核对，先前提交没有重复导入。

## 设备与方法

- 实机是 STM32F103CB，Flash 128 KiB、RAM 20 KiB，DBGMCU_IDCODE `0x20036410`；不是 F103ZE。
- 探针是 HPM5301EVKLite akaLinkPro，VID:PID `0d28:0204`，COM5。探针最终恢复本轮全部 10 项修改的固件。
- Scope、dbgstress、RTT speed、RTT seq 四个例程分别按 CB 容量重新构建。最终靶机保留 RTT seq 例程。
- 每个修改点先检查代码与适用的回归/故障注入，涉及可在当前设备运行的关键路径另做实机测试，通过后提交。文档修改按实现、测试接入与已取得的证据核对。
- 网页生产模块的实机测试使用 Python HID/PyUSB 原生适配器或 OpenOCD。界面布局/渲染使用测试替身；不能把这些结果表述为浏览器原生 WebHID/WebUSB 验收。浏览器界面通过 Computer Use 检查 r5 加载与模拟采样。

## 结果与限制

完整 `make test` 通过（[日志](2026-10-04/logs/r5-final-tests.log)），222 个模块语法检查通过，原 54 个 Markdown 检查通过。外部 ESP-IDF ELF 子用例因文件不存在跳过。新增报告另行做 Markdown 检查。

| 场景 | 实际结果 |
|---|---|
| RTT 60 MHz 新→旧→新对照，每版本 3×5 秒 | 原固件平均 2.917 MiB/s；新固件确认平均 2.922 MiB/s，确认轮序号检查无丢失、重复、坏记录和回退；约等于原来的 2.93 MiB/s |

RISC-V/H743 等其它目标的新增逻辑仅完成适用的离线检查，未冒充 F103CB 实机结果。跨标签页 HID 超时隔离仍有协议无事务编号的限制；物理拔插、长时间运行、浏览器后台节流、磁盘满/掉盘和外接器件需对应场景验收。短窗口性能结果不能证明长期稳定性。

上述降档窗口每轮还出现 1 条坏记录；在未打开 CDC 接收的 20 次启停后第一次最终测速，启动处也曾出现 2 条坏记录和两次序号跳变（约 598,039 字节的序号推算缺口），后两轮正常。未完全定位这类启动/错误恢复的数据完整性问题，不能声称所有启停场景零丢失。保留 [首次复核](2026-10-04/logs/r5-rtt-final-rate.log)、[重复复核](2026-10-04/logs/r5-rtt-final-confirm.log)、[原固件复核](2026-10-04/logs/r5-rtt-baseline-recheck.log) 和 [新固件复核](2026-10-04/logs/r5-rtt-current-recheck.log)，各轮实际时钟与读写错误均可核对。

诊断输出中的 `KB/s` 按每 1024 字节计算，本报告换算为 MiB/s；它测量的是探针侧 RTT→CDC 生产路径，不是浏览器 WebUSB Viewer 的端到端速率。原固件映像 SHA256 为 `110fe40388dd72faa0bcf0e48526f6bd096c7a02910b3d57f23fba1cdd6cd981`，新固件为 `897826ac9d665072be268aa4e9d01c458648a1499f0ce1417c0652827cadf497`。

## 验证中修正的问题

1. 本地中文 Windows 上三份固件主机测试使用明确 UTF-8 读取源代码。
2. Scope 批次开关移到采样设置，使其与采样操作一起呈现。
3. F103CB dbgstress 实际 ELF 含 `.ARM.exidx`，原解析器只加载 PROGBITS 会漏烧展开表。ELF 完整性项合入前修正为加载所有有文件内容的 ALLOC 节，排除 NULL/NOBITS；增加 ARM_EXIDX/INIT_ARRAY 内容与截断回归。完整镜像比较、实机烧录回读和重启后回溯均通过。
4. 文档与构建标记区分补丁导出环境的离线结果、本机实机结果和仍待验收的浏览器/外设场景。
