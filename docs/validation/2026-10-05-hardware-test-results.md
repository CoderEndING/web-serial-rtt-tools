## 本次测试

### STM32F103CB

- **时间：**2026-10-05 06:12–06:15；在线调试器复测约 07:34–07:36。
- **目标与固件：**STM32F103CB + akaLinkPro（SWD）；使用 `build-cb/fw.elf`，不是 F103ZE 固件。探针上同时连接 AT24C02、W25Q64；本次这组随机流程没有单独执行这两颗器件的读写验收。
- **流程：**随机次序为功能流程 → 调试压力 → 功能流程。两轮功能流程各执行 1 轮全场景和 1 次狂发/Scope 交替；三个子进程均退出码 0，每轮功能流程判决 10 通过 / 0 失败。
- **调试压力：**82 通过 / 0 失败，含 `bt`、`bt scan`、DWT 写观察点及连续 60 次停—走—停。8 次目标内存读取 FAULT 均由页面自动重试；目标没有意外复位，断点比较器没有泄漏。`bt` 因固件缺少 `.ARM.exidx` 展开表而不能提供完整展开链，`bt scan` 返回的是候选帧。
- **RTT Viewer：**60 MHz 档两轮实测 464.8 / 445.5 KB/s，错位读与溢出丢失均为 0，通过当前 300 KB/s 判线。
- **RTT 转发与存盘：**两轮页面 RX 均为 2.90 MB/s，探针自报搬运 2.58 / 2.48 MB/s。各记录 10.2 秒：29.49 MB 收数写成 29.42 MB；29.48 MB 收数写成 29.45 MB，均约 99.8% 一致，内容可读到 314 个 `hello world!`。
- **J-Scope：**1 变量 @2 µs 为 482.83 / 486.52 kHz（探针跳拍 51,442 / 39,987，USB 丢 26,170 / 15,179）；1 变量 @20 µs 均为 50.00 kHz（探针丢 4 次、USB 丢 0）。3 变量 @2 µs 为 91.09 / 91.10 kHz（探针跳拍约 1.22M，USB 丢 0）；3 变量 @20 µs 为 50.00 kHz（探针丢 3 / 4 次、USB 丢 0）。低速档损失低于 100 ppm 判线；高速档是链路上限测试，存在探针跳拍。
- **切换恢复：**两轮 3 变量高速 J-Scope 首次启动都遇到浏览器 `USBDevice.reset` 失败，停止采样并重连 HID/USB 后均恢复并完成测试。
- **Reset_Handler / `b main`：**先前低层复位脚本在 07:32 的 3 次复位中均未停住；随后从在线网页调试器载入 F103CB `dbgstress` 固件，07:34–07:36 连续 10 次都在 `Reset_Handler`（`0x080008A4`）停住，并能由 `b main` 停在 `main`（`0x0800008C`）。在线网页复测通过，但低层脚本与网页测试结果不一致的原因尚未定位，建议回到用户现场按实际操作路径再确认一次。

## 结果解读与限制

1. F103CB 本次 Viewer 为 445.5 KB/s，低于 F103ZE 历史的 616 / 609 KB/s；但它们不是同板、同线缆的配对测试。F103CB 用杜邦线，F103ZE 用调试排线；现有证据支持“连接条件可能影响速率”，不足以判定下降由本次架构修改造成。F103CB 尚缺一次同硬件、同固件、旧版/新版交替的 Viewer A/B 对照。
2. RTT Viewer 和 RTT 转发是不同路径。Viewer 约数百 KB/s、转发约 1–3 MB/s 的差距不能直接当作同一功能的回归。
3. 三块板的高速 J-Scope 项目都在冲链路上限；记录中会出现探针跳拍，H743 和 HPM 的部分 1 变量高速窗口还出现 USB 丢失。低速目标档的结果单独列出，不能用高速档“能启动”替代低速零丢样验收，也不能把高速档描述为全量无损。
4. 本文记录的是已有真机运行结果；临时 `tmp/` 日志与 JSON 作为原始证据保留在本地，不属于这份 Markdown 的跟踪文件。历史 F103CB 报告中列出的未覆盖项目和验证边界仍然有效，见[补丁逐项验收报告](2026-10-04-f103cb.md)。
