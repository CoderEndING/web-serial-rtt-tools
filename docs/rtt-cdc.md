# RTT → CDC 转发（akaLinkPro 探针侧桥）

终端页左侧那块「**RTT → CDC 转发（akaLinkPro）**」面板。它管的不是浏览器读 RTT，而是**让探针自己去读**：

```
目标 RTT 环形缓冲  ←SWD─  akaLinkPro 固件（自己轮询控制块、搬走数据、回写 RdOff）
                              └─→ CDC 虚拟串口 ─USB─→ 主机只要读一个 COM 口
```

好处很直接：主机侧不再"每轮三次 USB 往返"，实测 **2.4 MB/s 量级**（见下），而走 CMSIS-DAP 让主机读
大约只有 ~1.1 MB/s（探针文档给的数字）。

---

## 1. 怎么用（3 步）

1. **终端页 → 「连接探针」** → 在浏览器弹框里选 akaLinkPro（HID usage page `0xFF00` 的那个接口）。
   授权过一次之后，页面每次加载会**静默重连**，不用再点。
2. **填 RTT 地址**：
   - 手填（`0x20000000` 起，探针默认从这儿扫 64 KB）；
   - 或者点「**载入 ELF…**」——从 `.elf` 里读 `_SEGGER_RTT` 符号（和 RTT Viewer 一个逻辑），
     顺手把「搜索长度」收成 `0x1000`（已知确切地址就不用扫 64 KB）。
   - ⚠️ **Cortex-M7（H743 / H7B3 等）必须显式给 AXI SRAM**（如 `0x24000000`）：DTCM 是内核私有总线，
     探针走 AHB-AP 读不到，按默认区间扫会一无所获。
3. **「启动转发」**（或「**自动搜控制块**」让探针自己找）→ 然后回「**串口助手**」开这颗探针的 CDC 口
   （平时那个 VCOM，本机是 COM52），出来的就是 RTT 数据。

「停止」把 CDC 交回 UART（`uartx_set_cdc_source(0)`）。「SWD 时钟」是运行时调参（20/30/36/45/60 MHz，
出厂默认 45）；改完立刻生效，不用重启桥。

---

## 2. HID 协议（实现照 `app/hid/probe.js`）

报文固定 64 字节：`byte[0]` = Report ID（**1 = 主机→设备，2 = 设备→主机**），
`byte[1]` = Data Length（Command 1 字节 + 数据），`byte[2]` = Command。
WebHID 把 Report ID 单独传，所以代码里操作的是 **63 字节 payload**。

用到的命令：`0x10/0x11/0x13`（型号 / 序列号 / 固件版本）、**`0x31`（探针侧 RTT 桥）**。

`0x31` 的动作码（`api_param.c` 的 `RTT_ACT_*`）：

| 值 | 动作 | 请求字段（payload[2..]，都以 action 开头） |
|---|---|---|
| 0 | 停止 | — |
| **1** | 启动 | `addr(4) size(4) channel(1)`；addr=0 用默认区间，size=0 用默认 64 KB |
| **2** | 查状态 | — |
| **3** | 自动启动（自己搜控制块） | — |
| 7 | 运行时调参 | `swd_hz(4) chunk(2) flags(1) delay(1)`，flags bit0 = 丢弃模式 |
| 8/9 | 纯 SWD 基准 / 取结果 | 面板里没用到 |

响应：`payload[2]` = 返回码，`payload[3..]` = **12 个 32 位小端状态字**（位域见探针文档；面板显示的是
运行中 / 控制块地址 / 上行缓冲地址 / 已搬运字节 / 轮询·搬运次数 / 读错·RdOff 错 / 当前 SWD 档位）。

返回码：`0` 正常、`-1` SWJ_Clock 失败、`-2` SWD 初始化失败、`-3` 没找到控制块、`-4` 该档链路不可用、
**`-100` = "结果还没出来"**（固件 `s_start_rc` 的初值，**不是错误** —— 启动是排队给主循环做的，
所以刚点完启动看到的常常就是 -100，面板会显示"正在启动…"并继续轮询）。

## 3. 实测（2026-09-28，本机 akaLinkPro + STM32F103 板）

| 项 | 结果 |
|---|---|
| 连接 / 型号信息 | `akaLinkPro` · **FW 0.1** · SN `B4444F2110DDDAFE44800BBB0AE800E0` |
| 自动搜控制块 | 0.3 s 内 `running=true`，控制块 **0x2000000c**，上行缓冲 0x20000024 |
| **CDC 读出速度** | **5,054,465 B / 2 s = 2468 KB/s**（目标在死循环 printf `hello world!`） |
| 满速转发时的 HID | 连查 6 次状态 **6/6 成功**，每次约 **260 ms**；停止 0.3 s 生效 ✓ |
| 计数器 | `moved` 随 CDC 读出的字节同步增长（3.27 MB → 5.10 MB），读错 0 / RdOff 错 0 |
| 页面报错 | 无 |

> 目标板当时烧的是 RTT 洪水固件（`hello world!` 死循环），所以数字是"满速灌"的场景。

## 4. 踩过的坑（都已在代码里处理）

1. **一次只回一条**：探针 HID 是请求-应答式，同一时刻只能有一条在飞。
   早期 `info()` 用 `Promise.all` 并发发三条 → 第二条直接撞车（"上一条请求还没回来"）。
   现在 `info()` 串行发。
2. **迟到的响应会被算到下一条头上**：某条请求超时后，它的回包可能在**下一条请求**在飞时到达。
   现在 `_handleInput` 会比对 `payload[1]`（命令字）—— 对不上就**丢掉继续等**，而不是拿去满足新请求。
   （真机上就是这里把 `AUTOSTART` 的回包认成了型号回包，状态字全成了垃圾。）
3. **`-100` 别当错误**：见上，固件用它表示"排队中"。
4. **没有窗口的浏览器弹不出设备选择框**：`requestDevice()` 会**立刻 resolve 一个空数组**，
   看着像"没找到设备"，其实是 Edge 弹不出对话框（自动化里踩过）。给浏览器一个真窗口就好了。
5. **HID 与 CDC 互不干扰**：转发的 2.4 MB/s 走 CDC 端点，HID 照样 260 ms 一次应答 ✓（实测）。

## 6. 不在范围 / 已知边界

- 只做了 **RTT 桥**相关的配置。探针的其它 HID 配置（输出模式 / 5V / 时钟加速 / LED / 外部参考电压）
  没搬进来 —— 官方上位机 `akaLinkPro/docs/index.html` 里有。
- 面板没做 **纯 SWD 基准**（action 8/9）、**原始 DAP 透传**（action 4/6）、**读探针内存**（action 5）
  这几个调试动作。
- `丢弃模式`（action 7 的 bit0）协议层支持了，但面板上没给开关（它是排障用的：搬走但不送 CDC）。
